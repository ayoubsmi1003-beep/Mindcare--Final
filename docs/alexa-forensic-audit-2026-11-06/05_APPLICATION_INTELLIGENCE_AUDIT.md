## Explicitly bounded tool catalogue

`src/shared/alexa/agent.ts`, `agentSchemas`, also declares `search_knowledge`, `answer_general`, `navigate`, `ask_doctor` and `prepare_action`. Each request part carries at most three declared domain tools; the native global budget permits at most six calls and two concurrent calls. These are upper bounds, not evidence that all tool combinations are usable. Actions are proposals and require the existing human/SQL execution cycle; registry entries alone do not prove that the action is exposed, complete or authorized.

## Highest-value verification sequence

1. For each screen field, map the UI/service to the last applicable SQL signature and expected role, then map Alexa tool inputs/results and refusal states.
2. Build synthetic cases that distinguish created patients from patients seen, open from closed and unsigned notes, appointment date from visit date, and billed from collected money.
3. Verify complete cohort pagination, revision consistency, timezone and access-denied behavior before any cross-domain synthesis.
4. Introduce new reads only if an existing audited gate cannot answer; schema or migration changes require the repository's explicit decision process. No changes are made in this audit.
